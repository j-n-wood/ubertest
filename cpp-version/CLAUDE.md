# Project notes for agents (cpp-version)

Top-down game (raylib + Box2D v3, C++23). See `README.md` for build/run and architecture, the
`docs/` folder for subsystem docs, and `AGENTS.md` for testing guidelines.

## Data & assets

- **Unit definitions are hand-edited JSON.** `assets/units/droid_class_*.json` are the source of
  truth and are edited **directly**. They were originally generated by `tools/droid_tool` from
  the legacy uberdroid data, but **that converter is retired — do not regenerate**. Apply fixes,
  balance, and new fields straight to the JSON. (Don't "fix the converter and regenerate"; there
  is no round-trip anymore.)
- Weapon table is `assets/data/weapons.json`; other tunables live in the relevant `docs/` +
  header constants.
- `fireOffset` in a unit's `properties` is facing-relative `[x = lateral, y = forward,
  z = height]` in world units. Twin weapons fire a second bolt with the lateral `x` mirrored so
  the barrels straddle the centreline (see `docs/weapons.md`). Example: `droid_class_20`
  (twin weapon 7) uses `"fireOffset": [0.3, 0.0, 0.0]`.

## Conventions

- Prefer the built-in Read/Grep tools over shell `grep`/`awk`/`sed` for reading or searching
  files.
- Textures are owned centrally by `TextureManager` (`docs/textures.md`); GPU resources must be
  freed before `CloseWindow`.
- Subsystems (doors, chargers, effects, ...) follow the manager pattern: `init/update/destroy`
  with an idempotent `destroy()`, torn down before the Box2D worlds in `game_destroy`.
