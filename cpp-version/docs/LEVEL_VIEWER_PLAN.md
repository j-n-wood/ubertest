# Level Viewer Tool - Implementation Plan

This document describes the design and implementation plan for `level_viewer`, a tool for viewing and debugging TMX level files generated by `level_tool`.

## Overview

The level_viewer tool loads TMX level files from a folder (e.g., the ship1 output of level_tool), renders them using the shared rendering pipeline, and provides debug visualization modes for development and verification.

### Goals

1. Load multiple TMX levels from a nominated folder
2. Render tiles using the existing tileset (default.tsx / map_blocks.png)
3. Support multiple rendering modes (tileset-based, extended bump mapping, future 3D objects)
4. Provide debug views for tiles, waypoints, and physics data
5. Share rendering code with game via the `shared/` folder

### Non-Goals (Initial Version)

- Full game physics simulation
- Unit/droid rendering
- Real-time level editing

## Rendering Modes

The level renderer supports multiple modes for transforming TMX tile data into renderable geometry. The mode is selected at load time and determines how tile IDs map to visual representation.

### Mode 1: Tileset Atlas (Initial Implementation)

Renders tiles exactly as shown in Tiled editor:
- Each tile ID maps to a region of `map_blocks.png`
- UV coordinates computed from tileset definition (64x64 tiles, 2px spacing)
- Bump mapping uses `flat_normal.png` (no surface detail)

```cpp
struct TilesetAtlasMode {
    Texture2D atlas;           // map_blocks.png
    Texture2D bumpMap;         // flat_normal.png (default)
    int tileWidth = 64;
    int tileHeight = 64;
    int spacing = 2;
    int columns = 44;
};
```

**UV Calculation:**
```cpp
// For tile ID (1-based, 0 = empty)
int col = (tileId - 1) % columns;
int row = (tileId - 1) / columns;
float u0 = (col * (tileWidth + spacing)) / atlasWidth;
float v0 = (row * (tileHeight + spacing)) / atlasHeight;
float u1 = u0 + tileWidth / atlasWidth;
float v1 = v0 + tileHeight / atlasHeight;
```

### Mode 2: Extended Bump Mapping (Future)

Extends Mode 1 with per-tile bump texture coordinates:
- Diffuse texture from atlas (same as Mode 1)
- Bump coordinates reference separate bump texture atlas
- Tile metadata provides bump tile index

```cpp
struct ExtendedBumpMode : TilesetAtlasMode {
    Texture2D bumpAtlas;       // bump_tiles.png (separate atlas)
    // Per-tile bump mapping stored in tileset properties or separate config
    std::map<int, int> tileBumpIndex;  // tileId -> bumpTileId
};
```

### Mode 3: 3D Objects (Future)

Some tiles may be replaced with 3D models:
- Tile metadata indicates "render as 3D object"
- Model path stored in tileset properties
- Object position derived from tile grid position

```cpp
struct ObjectPlacement {
    int tileId;                // Which tile triggers this
    std::string modelPath;     // GLTF model to render
    Vector3 offset;            // Position offset within tile
    Vector3 rotation;          // Default rotation
    float scale;               // Model scale
};
```

## Coordinate Systems

### TMX Coordinates (Input)

- Origin: Top-left of map
- X: Right (columns)
- Y: Down (rows)
- Units: Pixels (tile position = grid * tileSize)

### Render Coordinates (Output)

Following existing conventions from `RENDERING_PIPELINE.md`:
- Origin: Center or corner of level (configurable)
- X: Horizontal (east)
- Y: Vertical (up) - tiles rendered on Y=0 plane
- Z: Horizontal (north)
- Scale: World units (1 tile = 1 unit, or configurable)

### Transformation

```cpp
// TMX pixel coords to render world coords
Vector3 tmxToRenderCoords(float tmxX, float tmxY, const TmxLevel& level) {
    // Center the level around origin
    float worldX = (tmxX / level.tileWidth) - (level.width / 2.0f);
    float worldY = 0.0f;  // Tiles on floor plane
    float worldZ = (level.height / 2.0f) - (tmxY / level.tileHeight);
    return {worldX, worldY, worldZ};
}
```

## Mesh Generation

Tile meshes are generated following the conventions in `tile_mesh.h`:

### Per-Tile Geometry

Each non-empty tile generates a quad:
- 4 vertices (BL, BR, TR, TL) in CCW order from above
- 2 triangles (indices: 0,2,1 and 0,3,2)
- Hardcoded normal: (0, 1, 0) facing up
- Hardcoded tangent: (1, 0, 0, 1) for bump mapping
- UV coordinates from tileset

### Batching

All tiles using the same texture pair (diffuse atlas + bump map) are batched into a single mesh for efficient rendering. For Mode 1 (tileset atlas), this typically results in 1-2 batches total.

```cpp
TileBatchCollection createLevelMeshes(
    const TmxLevel& level,
    const TmxTileset& tileset,
    RenderMode mode
);
```

## Implementation Phases

### Phase 1: Core Loading and Basic Rendering

**Shared code (`shared/level/`):**

1. **tmx_loader.h/cpp**
   - Parse TMX XML structure using tinyxml2 (already in project)
   - Extract map dimensions, tile layer, objects
   - Handle CSV tile data encoding

2. **tileset_loader.h/cpp**
   - Parse TSX XML structure
   - Load atlas image via raylib
   - Compute UV lookup table

3. **level_types.h**
   - TmxLevel, TmxTileset, TmxWaypoint structures
   - RenderMode enum

4. **level_renderer.h/cpp**
   - Mode 1 implementation (tileset atlas)
   - Generate tile meshes from TMX data
   - Create LevelRenderData structure

**Tool code (`tools/level_viewer/`):**

5. **main.cpp**
   - Argument parsing (--input folder path)
   - Window initialization
   - Main loop

6. **viewer_state.h/cpp**
   - State initialization
   - Level loading from folder
   - Cleanup

### Phase 2: Camera and Debug Visualization

7. **camera_controller.h/cpp**
   - Orbit camera mode
   - Free camera mode
   - Smooth transitions

8. **Waypoint visualization**
   - Draw waypoint spheres
   - Draw connection lines
   - Click-to-inspect (optional)

   **Reference geometry**
   - 1m diameter procedural sphere at origin (0,0,0)
   - Rendered with lighting shader for consistent appearance
   - Used to gauge unit conversion factors and scale
   - Toggle with `O` key (on by default)

9. **Debug overlays**
   - Grid rendering
   - Bounds visualization
   - Shader debug modes (via existing scene_renderer)

### Phase 3: Physics Stubs and Extended Modes

10. **Physics data stubs**
    - TileProperties with collision flags
    - STUB functions for collision generation
    - Visual placeholder for collision shapes

11. **Extended bump mode (Mode 2)**
    - Per-tile bump index support
    - Bump atlas loading
    - UV2 coordinate generation

12. **3D object stubs (Mode 3)**
    - ObjectPlacement structure
    - STUB rendering (placeholder cubes)
    - Model path resolution

## Usage Examples

### Basic Usage

```bash
# View levels using defaults (assets/ships/ship1/levels)
./level_viewer

# View levels from a custom path
./level_viewer --input ./output/ships/ship1/levels

# With custom asset path (input defaults to <asset-path>/ships/ship1/levels)
./level_viewer --asset-path ./my_assets
```

### Default Paths

The viewer uses sensible defaults for zero-configuration startup:

| Setting | Default Value |
|---------|---------------|
| Asset path | `assets` |
| Input path | `<asset-path>/ships/ship1/levels` |

This means running `./level_viewer` with no arguments will look for TMX files in `assets/ships/ship1/levels/`.

### Command Line Arguments

| Argument | Description |
|----------|-------------|
| `--input <path>` | Folder containing TMX files (default: `<asset-path>/ships/ship1/levels`) |
| `--asset-path <path>` | Base path for assets (default: `assets`) |
| `--level <n>` | Start at level N (default: 0) |
| `--scale <factor>` | World units per tile (default: 1.0) |
| `--help` | Show help |

## Future Considerations

### Game Integration

The `shared/level/` code is designed for reuse in the game:

```cpp
// In game code
TmxLevel level = loadTmxLevel("levels/level_0_maintenance.tmx");
TmxTileset tileset = loadTmxTileset("levels/default.tsx");
LevelRenderData renderData = createLevelRenderData(level, tileset, RenderMode::ExtendedBump);

// Use collision data for physics
physicsWorld.loadCollision(renderData.collision);

// Render each frame
drawLevelMeshes(renderData.tileMeshes, sceneRenderer);
```

### Tileset Enhancements

The TSX format supports custom properties per tile, which can be extended:

```xml
<tile id="42">
  <properties>
    <property name="collision" value="solid"/>
    <property name="bump_tile" type="int" value="5"/>
    <property name="model" value="models/console.gltf"/>
  </properties>
</tile>
```

### Multiple Tilesets

Future levels may use multiple tilesets. The architecture supports this by:
1. Storing tileset reference per layer
2. Creating separate texture batches per tileset
3. Maintaining UV lookup tables per tileset
